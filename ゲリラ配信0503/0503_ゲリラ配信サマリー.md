# デジイナゲリラ配信サマリー（2026-05-03）

**テーマ**: 言語火力・スキル設計の考え方（ゴール→プロセス→タスク→スキル）

---

## 今日の講義で一番覚えること

> **言語火力** = AIに伝えるための日本語を磨くこと。曖昧な言葉は曖昧な結果しか生まない。

---

## 1. AIとの認識のズレ

### みかんの実験

「みかんは〇〇」の〇〇に入る言葉を人間に聞くと → 甘い、丸い、黄色い、冬に美味しい、こたつの上にある…（14パターン）

同じ質問をAIに聞くと → 手が黄色くなる、向き方に性格が出る…（人間が思ってない回答）

**なぜこうなるか？** → 質問が曖昧だから。カテゴリーが指定されていない。

### 対策：カテゴリーを指定する

| 質問 | AIの回答 |
|------|---------|
| みかんは〇〇（曖昧） | バラバラなカテゴリーの回答が来る |
| みかんの**味覚**に関することを5つ | 甘酸っぱい・後味すっきり…（味覚に絞られる） |
| みかんの**視覚**に関することを5つ | ビタミンカラー・艶がある…（視覚に絞られる） |

## 2. 言語火力とは

```
AIに伝わるようになった = 日本語で動かせるようになった
        ↓
その日本語が曖昧 = 曖昧な結果しか出ない
        ↓
言語火力を高める = AIが正しく動く
```

**飲み物の例:**

| 指示 | AIが買ってくるもの |
|------|-----------------|
| 飲み物買ってきて | 水・お茶・コーラ…何でも |
| コーヒー買ってきて | アイス？ホット？ブラック？ |
| アイスコーヒー200円以内 | まだ銘柄が決まらない |
| 冷たいワンダーモーニングショット | **それしか買ってこない** ✅ |

→ **具体的なゴールとプロセスを伝えないと期待通りの結果は得られない**

## 3. スキル設計の基本フレームワーク

**ゴール → プロセス → タスク → スキル** の順で設計する。

### 電子書籍作成スキルの例

#### ①ゴール
```
漫画・図鑑入りの、KDPで出版申請できる状態の原稿を作る
```

#### ②プロセス（どんな工程が必要か）
```
リサーチ → 企画 → 執筆 → チェック → 図作成 → 漫画シナリオ
→ キャラ設定 → 漫画作成 → 編集・構成
```

#### ③タスク（各プロセスで何をするか）

| プロセス | タスク例 |
|---------|---------|
| リサーチ | 売れるテーマ調査・Kindleランキング・検索されてるワード・スパ表紙のワード |
| 企画 | ターゲット・ペルソナ・テーマ策定・構成（離脱されない章立て）・得点 |
| 執筆 | 文章量（1万字/2万5千字）・文体（です・ます/言い切り/親密）・目次（5章/8章） |

#### ④スキルが確定する
```
タスクが決まる → 何のスキルが必要か自動で決まる
リサーチスキル・企画スキル・執筆スキル…それぞれ独立したスキルとして設計
```

---

## 4. エージェント設計との関係

プロセスとタスクの間に**エージェント担当**が決まる。

```
リサーチプロセス → リサーチ担当エージェント（リサーチスキルを持つ）
企画プロセス    → 企画担当エージェント（企画スキルを持つ）
執筆プロセス    → 執筆担当エージェント（執筆スキルを持つ）
```

→ **スキルはエージェントに持たせるためのもの**（5/24講義と接続する概念）

---

## 5. スキル作成の実践的な手順

### 自分でイメージできないものは作れない（フリーレン的極意）

> 言語化できないものはAIには伝わらない。曖昧なスキルしか出来上がらない。

**イメージがつかない時の対処法:**

```
1. 何が困っているか・何を解決したいかを明確にする
2. クロードコードに「プロセスをマインドマップで出して」と頼む
3. それをもとに壁打ちを始める
4. 言語化しづらいなら → AIに「うまく伝わる言葉に整えて」と頼む
```

### スクショ貼り付けで一発設計

```
自分が考えたプロセス図をスクショ → クロードコードに貼り付け
→「このプロセスを元に電子書籍スキルを作って。まず計画を提案して」
→ 大筋が出てくる → 中身を突き詰めていく
```

---

## 6. デジーナエージェントとの関係

```
デジーナエージェント = ゴール→プロセス→タスク→スキルの設計が完成したもの
                    = 電子書籍作成の大元のワークフローが組み込まれている
```

**カスタマイズの進め方:**
- 漫画100ページ欲しい → プロセスを組み直す
- 図の向きを縦長にしたい → 執筆スキルのタスクを変える
- 自分なりの電子書籍作成スキルを育てていく

---

## まとめ・今日の要点

1. **AIとの認識のズレ**を意識する（曖昧な質問 = 曖昧な結果）
2. **カテゴリーと制約を明示**するだけで回答の質が激変する
3. スキル設計は **ゴール → プロセス → タスク → スキル** の順で考える
4. **自分が理解していないものは作れない** → まずプロセスを言語化する
5. デジーナエージェントは**土台として使い、自分流にカスタマイズ**していく
